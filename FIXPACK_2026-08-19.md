### A1. Real vs bookkeeping, redefined (fix #1)
Doctrine (Edmund, verbatim intent 2026-08-18): "it doesn't matter if
it's a pure score putting something on the board or the assessor —
they are equally valid."
- A move is REAL iff it changes board membership or final tier —
  regardless of driver (score crossing, assessor stamp, override).
- "Bookkeeping" shrinks to: stamp changes with NO tier consequence.
- The assessor VETO case is also real news (CSL 2026-08-18: raw score
  crossed the entry line, assessor ruled it off the same night —
  today that renders as ledger noise "off board→None"). Render it as
  a story: crossed the line, kept off by judgment, WITH the
  assessor's stored reason when one exists — and when it doesn't,
  the story is exactly "crossed the line, kept off" with NO invented
  thesis (Edmund 2026-08-19; machinery does the assessing, Claude
  never hand-writes one). Assessor badges stay dark regardless
  (V3 #11 unchanged). Note: 'None' arrives as a STRING in
  assessed_tier — handle it explicitly, never print it to a reader.

### A2. Membership + counts from the shared resolver (fix #2, V3 #14)
CORRECTED 2026-08-19 (Edmund): the dirty tree imports board_membership
from api.routers.board — WRONG twice over: (a) pipeline must never
import the API (the boundary runs the other way), and (b) that
function reads MAX(date) only, so regenerating the 08-18 edition
would stamp TODAY'S board onto yesterday's paper.
- EXTRACT the resolver to a new pipeline module next to
  pipeline/tiers.py (e.g. pipeline/board_membership.py) exposing
  `board_membership(conn, as_of: date)` (and the underlying
  _resolve_tier). It resolves against the snapshot FOR that date —
  MAX(date) only as the default when as_of is None.
- api/routers/board.py then imports and consumes the pipeline module
  (api -> pipeline is the allowed direction). Behavior of live /board
  must be byte-identical — prove with a before/after response diff.
- daily_report.py (_masthead, _board_moves, counts) uses the
  extracted resolver with the EDITION'S date, so a string-'None'
  stamp or raw-floor-guard drop can never fabricate or hide a move.
- Finish the existing working-tree diff to this spec; do not start a
  parallel one.
