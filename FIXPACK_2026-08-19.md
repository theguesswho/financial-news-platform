## SESSION A — the report tells the whole truth
Files: pipeline/daily_report.py, the 8-K ingest module (find the
"8-K ingest complete" counter). NOTHING else. This is a truthfulness
fix to an existing surface, not a scoring or report-voice redesign.

### A1. Real vs bookkeeping, redefined (fix #1)
Doctrine (Edmund, verbatim intent 2026-08-18): "it doesn't matter if
it's a pure score putting something on the board or the assessor —
they are equally valid."
- A move is REAL iff it changes board membership or final tier —
  regardless of driver (score crossing, assessor stamp, override).
- "Bookkeeping" shrinks to: stamp changes with NO tier consequence.
- The assessor VETO case is also real news (CSL 2026-08-18: raw score
  crossed the entry line, assessor ruled it off the same night —
  today that renders as ledger noise "off board→None"). Render it as
  a story: crossed the line, kept off by judgment, with the
  assessor's reason. Note: 'None' arrives as a STRING in
  assessed_tier — handle it explicitly, never print it to a reader.

### A2. Membership + counts from the shared resolver (fix #2, V3 #14)
- _masthead (and every count/diff in daily_report.py) derives "on the
  board" from api/routers/board.py board_membership / _resolve_tier —
  never its own COALESCE. Import it or extract the resolver to a
  shared module both import (preferred if the import direction is
  awkward); either way ONE definition, zero copies.
- The _board_moves diff must classify with the same resolution, so a
  string-'None' stamp or a raw-floor-guard drop can never fabricate
  or hide a move again.

### A3. Significance: exits and entries always get a line with a cause
(fix #3)
- Every membership change gets at minimum a one-sentence storied item
  (symbol, direction, cause, score path) — the compact "Also moved"
  ledger remains only for rank shuffles and tier moves WITHIN the
  board when the day is crowded (>10 membership changes).
- A name that entered within the last 3 sessions and now exits is
  flagged as such in its item ("in and out inside a week") — that
  pattern is information, not noise (FDS).

### A4. Ingest hygiene (fix #4)
- The 8-K inserter treats a uq_filings_url unique-violation as a SKIP
  (already-have-it), counted separately: "15 new, 11 already stored,
  0 errors". Use ON CONFLICT (url) DO NOTHING or catch the specific
  UniqueViolation only — real errors must still count as errors.
